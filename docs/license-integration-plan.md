## 二、调研结论与接入方式

Java 项目为 Spring Boot 2.7.18、Java 8、MyBatis-Plus 与 MySQL 后端，已有发卡、激活、心跳、注销、冻结、会话管理及试用能力；该目录没有管理前端源码。

实施前的授权并非永久绑机，只限制最近 120 秒内的其他设备使用。原 `appStatus` 仅在激活响应中返回，没有参与服务端产品校验；试用记录也没有产品维度。因此只在 Cue 增加一个输入框不能满足已确认需求。

实施采用“复用现有数据库与管理能力，增加 Cue 专用客户端接口”的方式。其他产品的接口路径、请求响应和设备规则保持兼容；不复制整个 Java 服务，也不在 Cue 内运行 Java 或数据库。

本轮扩展现有管理网页，不重做管理后台，不增加账号注册、支付、购卡商城、套餐权限分级或自动续费。卡密从首次激活起按现有 `durationHours` 连续计时；退出、冻结和解绑均不重置到期时间。卡到期后可输入新卡，试用期间也可转为付费卡。

## 三、Java 服务端任务与接口约定

### 1. Cue 专用接口

下列路径均相对于 API 入口，继续使用 `{code, message, data}` 响应；HTTP 状态正常不代表业务成功，必须检查 `code`。

| 方法与路径 | 请求 | 用途 |
| --- | --- | --- |
| `POST /cue/license/activate` | `licenseKey`、`machineId`、`clientVersion` | 检查 Cue 卡、首次绑机及计时；同机重新启动恢复会话 |
| `POST /cue/license/heartbeat` | Bearer Token；正文 `machineId` | 校验产品、卡状态、设备绑定及当前会话，刷新心跳 |
| `POST /cue/license/deactivate` | Bearer Token；正文 `machineId` | 释放当前会话，不解除设备绑定 |
| `POST /cue/trial/activate` | `machineId`、`clientVersion` | 首次领取或恢复尚未到期的 Cue 试用 |
| `POST /cue/trial/heartbeat` | Bearer Token；正文 `machineId` | 检查 Cue 试用和设备是否仍有效 |
| `POST /admin/license/unbind/{id}` | 管理员 Bearer Token | 仅对 Cue 卡清除绑定并作废全部会话 |

激活成功返回 `token`、`appStatus=2`、`mode`（`license` / `trial`）、`expiredAt`、`serverTime`、`heartbeatIntervalSeconds=30`、`offlineGraceSeconds=120`；付费卡另返回 `licenseType`、`durationHours`。心跳成功返回 `valid=true`、`appStatus=2`、`mode`、`expiredAt`、`serverTime`。新接口时间统一为 Unix 毫秒，旧接口的时间格式不变。

沿用已有错误码；新增 `1006` 表示卡密不属于 Cue、`1007` 表示绑定其他设备、`1203` 表示会话心跳超时可重新验证。`1202` 保留给被注销、管理员下线或找不到的会话，客户端不自动反复激活绕过下线。新接口明确校验 Token 类型、`appStatus=2` 和设备；客户端不持有 Java 的 JWT 签名密钥。

### 2. 固定绑机与旧产品兼容

- `license` 增加可空 `bound_machine_id VARCHAR(128)`；仅 `appStatus=2` 使用。首次激活对卡记录加事务行锁，产品、冻结、期限、绑定校验通过后才写绑定和首次到期时间。
- 同设备重激活创建或更新有效会话、刷新心跳并轮换 JWT 的 `jti`，旧会话 Token 不再有效。新 Cue 会话的 `token_jti` 存 UUID，不存完整 JWT。
- Cue 心跳同时检查当前绑定、会话状态、`jti` 与超时。修复现有“超时后重激活复用旧心跳”的问题，避免恢复后立即再次失效。
- 旧 `/license/*` 入口遇到 Cue 卡或 Cue Token 必须拒绝，旧 `/trial/*` 心跳也拒绝 Cue Token，避免绕开产品限制；旧产品卡拒绝进入 Cue 接口。旧产品正常请求保持原规则。
- 管理员解绑需事务锁定卡、清除绑定并作废会话；不修改激活和到期时间。解绑后的下一次成功激活绑定新设备。管理员操作说明要求先退出旧电脑上的 Cue；解绑不会作废卡密本身，持有卡密者仍可再次尝试激活。
- 已激活卡不能通过管理更新接口跨 Cue 与旧产品修改 `appStatus`，防止已经建立的授权语义被悄悄改变；返回明确业务错误。

### 3. 独立试用与管理

- 新建 `cue_trial_record` 表，沿用现有试用记录结构，`machine_id` 唯一；旧 `trial_record` 不迁移、不修改资格。
- 首次试用由用户点击触发并连续计时 24 小时；未到期重复请求恢复原到期时间，不延长；过期拒绝重新领取。并发领取以唯一约束和冲突后读取原记录保证不重复计时。
- 复用现有 `/admin/license/generate`，请求传 `appStatus=2`。给现有卡密查询增加可选 `appStatus` 过滤，绑定设备字段随管理查询返回；增加受管理员认证保护的 Cue 试用查询接口 `/admin/cue/trial/page`。
- 不改变旧产品 Token 校验规则来批量踢出现有客户端。修正公共激活代码写入完整 JWT 与 `VARCHAR(64)` 不一致的问题时，旧产品仍保持原有会话查找语义，不强制迁移旧 Token。
- 新接口日志只记录结果、错误码和耗时；对已有日志中密码、卡密、Token 字段做脱敏，避免客户端自动验证后反复写入完整凭据。

提供增量迁移 SQL、接口样例、发卡/查询/冻结/解绑操作说明与旧产品兼容测试。数据库实际结构可能与仓库 DDL 不同，执行迁移前核对；不直接用建表脚本覆盖线上数据库。

## 四、管理网页任务

- 发卡表单新增 `Cue（2）`，请求中的 `appStatus` 保持数字；管理类型定义从 `0 | 1` 扩展到 `0 | 1 | 2`。保留现有 0/1 的标签、选择与默认发卡行为。
- 卡密列表正确显示 Cue，兼容接口已有数值或字符串表示；桌面和移动筛选面板均增加产品筛选，支持全部、鼠标宏、自瞄、Cue，与后端新增的可选 `appStatus` 查询字段一致。值 0 必须正常发送，不能被真假判断丢弃；清除筛选后不发送此字段，并回到第一页。
- 发卡结果展示、复制、刷新与列表查询继续复用现有交互；时长、备注、冻结解冻、删除等原有功能不扩展业务含义。现有前端与后端若存在历史字段不一致，单独记录，不借本轮改写其他软件的规则。
- 管理网页本轮不增加试用管理新页面或解绑按钮；管理员使用接口说明操作 Cue 独立试用查询与解绑。
- 使用本地模拟响应及测试服务验证三种产品发卡和筛选，再执行 TypeScript/Vite 构建。保持原管理页面风格，不引入 Cue 的桌面磨砂设计。

## 五、Cue 客户端任务

### 1. 授权模块与保存

- 在 Go 层增加独立授权模块，负责 HTTP、设备标识、授权状态、心跳与注销；前端通过 Wails 调用，不直接请求 Java 服务。
- 新增前端接口 `GetLicenseStatus`、`ActivateLicense`、`StartTrial`、`RetryLicense`、`ForgetLicense`，以及 `license-status` 事件。状态包含检查中、待激活、卡密有效、试用有效、断网容错、已锁定，以及到期时间、剩余容错和可显示的原因；不返回 Token 或完整卡密。
- macOS 使用平台 UUID，Windows 使用系统 MachineGuid，结合固定 Cue 命名空间生成 SHA-256 设备标识。服务端只接收摘要；获取失败时明确报错，不用每次变化的随机值绕过绑机。卸载或清理 Cue 配置不会改变设备标识；重装系统或更换主板可能需要管理员解绑。
- 自动验证所需的卡密保存到 macOS Keychain / Windows Credential Manager；Token 只留在运行内存。普通配置仅记录授权模式和脱敏信息；凭据保存失败应明确提示，下次启动可重新输入，不降级明文保存。
- API 地址由构建配置注入，发布版不向普通用户提供任意修改入口；开发允许环境变量指定本地测试服务。未配置或不可达时保持待验证，不默认放行。现有 HTTP 地址用于测试联调，正式分发前安排 HTTPS 入口并启用正常证书校验，避免卡密和 Token 明文传输；客户端不跳过 TLS 校验。

### 2. 生命周期与功能控制

- 启动先显示紧凑激活面板；有已保存授权则自动联网验证，成功后才进入原有菜单条。没有历史有效会话的启动不能借用 120 秒容错直接进入。
- 每 30 秒心跳，单次请求超时 8 秒；临时网络错误或服务 5xx 时重试，宽限期以最后一次成功验证起最多 120 秒计算，不随每次失败延长。授权本身到期不会延长到容错结束。
- 明确的冻结、到期、绑机冲突、产品不匹配、会话被撤销立即锁定；网络恢复或休眠唤醒先重新验证。可恢复的会话超时可自动重新获取授权，管理员下线不进入无限自动激活循环。
- 授权恢复只解锁界面，不自动开始麦克风、系统音频或重新发送问题。正常退出短时尝试注销付费会话，网络异常不能拖住退出；保存的卡密和固定绑定保留。
- Go 统一校验覆盖手动提问、快捷键、开始转录、截图问答、页面记录、后台会议纪要和本地助手入口。不能仅靠前端按钮禁用。
- 授权失效先拒绝新任务，再取消回答、页面记录和后台纪要，停止音频并释放模型；停止转录的收尾不能另起纪要请求。保留已写入的会议、转录和用户配置，不清空数据。
- 工作任务使用随本次有效授权创建、失效时取消的上下文。处理异步恢复、切卡和退出竞态，旧请求不能重新把已锁定状态改成已授权。

### 3. 界面与文档

- 复用现有磨砂样式实现紧凑激活面板：卡密输入、激活、领取 24 小时试用、重试、退出；联网验证期间显示进度和明确失败原因。
- 授权成功后的原菜单条与业务界面保留。在设置中增加授权信息、到期时间、更换卡密/转为付费卡和清除本机授权入口；清除本机授权不等于管理员解绑。
- 失效后回到激活面板，保留未发送问题及已经生成的内容；重新激活后可继续查看。激活面板允许拖动，焦点切换不滚动页面、不让菜单条上跳。
- 补充中文 README 的激活、试用、绑机、断网、换机和开发联调说明。界面预览使用明确标注的模拟状态；真实桌面调试也执行授权检查，不新增可用于发行版的免验证开关。
