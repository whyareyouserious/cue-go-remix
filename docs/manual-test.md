# 手工测试步骤

## 本轮补测：蓝牙耳机无字幕修复

保持刚才同一副蓝牙耳机和系统输入设置。新版启动后，点击“开始会话 → 显示”，连续说 10～15 秒，再停顿 2 秒；应在说话中更新“我 · 正在说”，停顿后保存历史。若仍无字或出现提示，直接结束会话并退出 Cue，告诉开发者；无需反复切换模型或密钥。开发者会对照每两秒的采集帧数、音量和麦克风恢复事件。

## 中文实时转写完整验收

由开发者启动新版 Cue，用户完成以下操作，最后退出应用并告诉开发者“测完了”。开发者读取本地诊断日志，核对首次出字、增量更新、队列等待和尾句处理。

1. 打开“设置 → 音频”，确认选中“本地实时（中文）”并保存。这个模式无需语音 API Key；先关闭“采集系统音频”，单独测试麦克风。
2. 点击“开始会话”→“显示”，打开“转录历史”。连续说：“今天我们讨论项目进度，请介绍一下现在完成了哪些功能。”说话过程中应持续出现“我 · 正在说”的文字，允许随上下文修正；停顿后整句进入历史。不应等到结束会话或约 15 秒后才首次出字。
3. 再说两三句普通话，包含容易混淆的词，例如“实时转录”“第三方接口”“项目进度”。检查字幕和历史是否统一为简体，留意错词、漏字、重复和停顿后确认整句的等待时间。麦克风标为“我”，不会自动填入提问框；点击对应历史记录可以手动提问。
4. 结束会话，再到“设置 → 音频”打开“采集系统音频”并保存，然后重新开始。播放一段清楚的中文视频或会议声音，建议佩戴耳机，避免扬声器同时被麦克风录入。系统声音应显示为“对方”，说话未结束时，暂定文字就应持续填入提问框；最终文字替换同一句，不重复追加。
5. 暂时不要按 Enter，确认没有自动发起回答。手工编辑输入框中的问题，后续字幕不应覆盖编辑。随后可点击一条历史记录，或清空输入框等待下一句，按 Enter 才发起大模型回答；已发送的同一句后续修正不应重新填回输入框。聊天服务需另行配置，回答失败与本地转写分别记录。
6. 说一句短话后点击“结束会话”，检查尾句被保存、实时字幕清空。最后点击悬浮条最右侧 × 退出 Cue，告诉开发者测试结果；有问题时注明步骤、说的原话及看到的错误文字，无须提供 API Key。

本机公开中文样本的双路实时回放已经能在说话中产生多次暂定结果；这不等于真实麦克风、噪声环境或 Windows 设备的延迟与准确率保证。请重点反馈“说话中是否出字、停顿后多久确认、哪些词识别错误”。

## 界面与第三方设置回归

本节验收磨砂玻璃界面和第三方设置稳定性，不要求调用真实模型。由开发者启动新版，用户操作，完成后关闭 Cue；再由开发者读取本地日志分析。

1. 将 Cue 放在浅色窗口上方，确认磨砂玻璃悬浮条外没有黑色底框或外投影。点击“显示”展开回答卡，打开设置和转录历史，检查各面板外的空白区域也能透出桌面；点击“隐藏”应恢复小条。
2. 点击齿轮 → 密钥 → 第三方中转，在 OpenAI 和第三方之间切换两三次；窗口应始终存在。
3. 点击第三方 API Key 输入框。可以填写自己的 Base URL、密钥和模型，或只测试聚焦；密钥只在本机填写，无须发送到聊天。
4. 填写了配置时点击“保存设置”，重新打开检查第三方选项和模型。已保存的密钥应显示“已保存，留空继续使用”，不会回显明文。未填写时直接关闭设置即可。
5. 在工具条、回答卡、设置及历史面板的边缘或紧邻的透明空白处按住鼠标拖动，无须对准“拖动”按钮。检查按钮可点击、输入框能输入、回答文字可选中、历史和设置可滚动。面板周围的拖动区域会接收鼠标，远离面板的空白仍穿透。点击工具条的透明度按钮，检查滑块能否正常拖动。
6. 最后点击悬浮条最右边的 × 退出 Cue。告诉开发者“测完了”，若有问题说明发生在第几步。

本节界面回归不需要开始会话或授予采集权限。语音测试按上方“中文实时转写”步骤进行：对方暂定文字和最终文字持续更新输入框，按 Enter 才请求回答，不自动逐句发送。

## 日志

- macOS：`~/Library/Application Support/cue-go-remix/logs/cue.log`
- Windows：`%AppData%\cue-go-remix\logs\cue.log`

日志包含时间、进程 ID、设置页打开、提供商选择、密钥框聚焦、保存结果、窗口尺寸、模型请求起止耗时、监听状态与退出事件，以及本地实时识别的首次出字、较慢解码耗时、排队时长、首次暂定与最终文字字数。仅记录固定类别和数值，不记录密钥、完整接口地址、模型名称、转录内容或问题/回答正文。文件达到 1 MiB 后，在下次启动时轮换为 `cue.previous.log`。

正常退出应有 `quit-request`、`shutdown-start`、`shutdown-done`。若窗口意外消失，开发者将结合最后一个操作事件、进程状态与系统崩溃记录判断，不能仅凭缺少退出日志就认定崩溃。
