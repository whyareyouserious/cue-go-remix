# 手工测试步骤

## 本轮补测：结构拆分后的启动

已启动重新构建的 macOS Cue，使用独立临时数据目录，不读取原配置和会议文件。本次没有配置正式授权地址，先验收启动面板即可：

1. 确认看到“激活 Cue”、卡密输入框、激活、试用及重新验证按钮，没有“无法连接桌面服务”提示。
2. 在面板边缘拖动，检查窗口位置是否连续变化、是否有异常跳动；点击输入框检查聚焦，无需填写卡密或领取试用。
3. 点击面板右上角退出，反馈“测完了”及异常步骤。开发者读取 `/private/tmp/cue-structure-panel-check/logs/cue.log`，检查窗口和退出事件。

本轮 28 项界面自动化和 Go 回归已通过；下方完整功能测试需在测试后端与授权具备后执行，不能用启动面板正常代替音频和线上授权验收。

## 本轮补测：Cue 授权与原有功能

前提：当前 Java 授权服务和 HTTPS 入口尚未部署，不能把本地 mock 或浏览器预览当作线上可用。开发者先提供连接独立测试后端的应用及测试卡，或明确标注模拟模式的浏览器预览；不使用线上账号、真实用户或生产卡密。真实桌面应用不跳过授权，下方原有界面/音频步骤须在测试授权成功后进行。

1. 首次启动先看到可拖动的激活面板，工具条与采集功能不可用。点击卡密输入框、切换焦点和拖动窗口，面板不应上跳或滚动出视口；小屏中激活、试用、重试、退出按钮均可达。
2. 分别输入错误卡、鼠标宏/自瞄测试卡，检查明确提示且仍停留在激活面板。输入正确 Cue 测试卡，连续点击激活或按 Enter，不应重复提交；成功后才显示原工具条，不自动开始录音、截图或发送问题。
3. 退出并重新打开应用，不再次输入卡密也应联网恢复。同机重装 Cue 不应解除服务端绑定；只验证独立测试环境，不操作现有生产授权。系统凭据拒绝访问或保存失败时，检查明确错误/下次需重新输入的提示，退出不能无限等待。
4. 在未领过 Cue 试用的测试电脑上主动点击领取，记录到期时间；退出重开及重复恢复均不延长。到期后不得再次领取。用测试服务的受控时钟验证 24 小时边界，不修改用户系统时钟或现有试用数据。
5. “设置 → 授权”应显示模式、到期时间和脱敏卡密。试用中输入付费测试卡后切换成功；输入错误替换卡应保留当前有效授权。清除本机授权先弹确认，取消不变，确认返回激活面板；会议与设置保留，服务端绑定和试用资格不重置。
6. 在测试后端临时停止响应，已有有效会话可显示断网容错；以最后一次成功验证起计，达到 120 秒必须停止受限功能，不因反复失败延长。没有历史有效会话的启动不能进入容错。恢复测试服务并重新验证后，原问题和已生成回答保留，录音和问题发送须用户主动开始。
7. 测试后台冻结、到期、撤销会话时，客户端收到明确拒绝后立即锁定；检查正在进行的回答、页面记录和音频均停止。被取消录音的收尾不得借重新激活自动发出纪要请求。仅会话超时可自动恢复，管理员撤销不能被自动重激活绕过。
8. 使用两台测试电脑验证固定绑机：第二台同卡激活被拒绝。退出旧电脑 Cue，由管理员调用测试环境解绑接口，新电脑再激活成功；到期时间不变。管理网页本轮没有解绑按钮，清除本机授权不替代此步骤。
9. 短休眠和超过 120 秒休眠分别验证恢复流程；断网/恢复时快速切卡或退出，旧响应不得覆盖新状态或重新启用旧任务。此项必须真机验证，浏览器桥接测试不替代平台休眠结果。
10. 授权成功后继续下方原有界面、听写和第三方设置回归。最后正常退出并反馈“测完了”、异常步骤与界面错误文字；无需发送卡密、Token 或 API Key。

管理网页另用本地模拟数据验证：0/1/2 产品发卡仍传数字，默认鼠标宏；数字和字符串 Cue 标签一致；桌面与移动产品筛选、0 值、清除/重置回第一页以及分页保留条件正确。备注筛选和批量到期时间属于已有后端契约差异，不列为本轮修复通过。

## 本轮补测：透明度与菜单按钮

先只保留菜单条，连续开关“设置”五次，观察菜单条是否还会先向上弹再回位；随后展开回答面板再开关设置，也应保持原位。

1. 保持只显示菜单条，连续点击透明度按钮开关几次，再拖动透明度滑块；菜单条应保持原位置，透明度面板在下方展开。
2. 点击“显示”展开回答面板，重复上一步；菜单条和回答面板都不应被推移。
3. 分别点击设置、使用指南：第一次打开，第二次关闭，第三次能再次打开。进入设置的任一子页后，再点菜单条设置按钮也应关闭。
4. 在设置、指南、透明度之间切换，应只保留当前弹层；关闭设置不会保存未提交的修改。
5. 测完关闭 Cue，并反馈“测完了”及异常步骤，便于结合日志检查。

## 本轮补测：蓝牙耳机无字幕修复

保持刚才同一副蓝牙耳机和系统输入设置。新版启动后，点击“开始会话 → 显示”，连续说 10～15 秒，再停顿 2 秒；应在说话中更新“我 · 正在说”，停顿后保存历史。若仍无字或出现提示，直接结束会话并退出 Cue，告诉开发者；无需反复切换模型或密钥。开发者会对照每两秒的采集帧数、音量和麦克风恢复事件。

## 中文实时转写完整验收

由开发者启动新版 Cue，用户完成以下操作，最后退出应用并告诉开发者“测完了”。开发者读取本地诊断日志，核对首次出字、增量更新、队列等待和尾句处理。

1. 打开“设置 → 音频”，确认选中“本地实时（中文）”并保存。这个模式无需语音 API Key；先关闭“采集系统音频”，单独测试麦克风。
2. 点击“开始会话”→“显示”，打开“转录历史”。连续说：“今天我们讨论项目进度，请介绍一下现在完成了哪些功能。”说话过程中应持续出现“我 · 正在说”的文字，允许随上下文修正；停顿后整句进入历史。不应等到结束会话或约 15 秒后才首次出字。
3. 再说两三句普通话，包含容易混淆的词，例如“实时转录”“第三方接口”“项目进度”。检查字幕和历史是否统一为简体，留意错词、漏字、重复和停顿后确认整句的等待时间。麦克风标为“我”，不会自动填入提问框；点击对应历史记录可以手动提问。
4. 结束会话，再到“设置 → 音频”打开“采集系统音频”并保存，然后重新开始。播放一段清楚的中文视频或会议声音，建议佩戴耳机，避免扬声器同时被麦克风录入。系统声音应显示为“对方”，说话未结束时，暂定文字就应持续填入提问框；最终文字替换同一句，不重复追加。
5. 暂时不要按 Enter，确认没有自动发起回答。手工编辑输入框中的问题，后续字幕不应覆盖编辑。随后可点击一条历史记录，或清空输入框等待下一句，按 Enter 才发起大模型回答；已发送的同一句后续修正不应重新填回输入框。聊天服务需另行配置，回答失败与本地转写分别记录。
6. 说一句短话后点击“结束会话”，检查尾句被保存、实时字幕清空。最后点击悬浮条最右侧 × 退出 Cue，告诉开发者测试结果；有问题时注明步骤、说的原话及看到的错误文字，无须提供 API Key。

本机公开中文样本的双路实时回放已经能在说话中产生多次暂定结果；这不等于真实麦克风、噪声环境或 Windows 设备的延迟与准确率保证。请重点反馈“说话中是否出字、停顿后多久确认、哪些词识别错误”。

## 界面与第三方设置回归

本节验收磨砂玻璃界面和第三方设置稳定性，不要求调用真实模型。由开发者启动新版，用户操作，完成后关闭 Cue；再由开发者读取本地日志分析。

1. 将 Cue 放在浅色窗口上方，确认磨砂玻璃悬浮条外没有黑色底框或外投影。点击“显示”展开回答卡，打开设置和转录历史，检查各面板外的空白区域也能透出桌面；点击“隐藏”应恢复小条。
2. 点击齿轮 → 密钥 → 第三方中转，在 OpenAI 和第三方之间切换两三次；窗口应始终存在。
3. 点击第三方 API Key 输入框。可以填写自己的 Base URL、密钥和模型，或只测试聚焦；密钥只在本机填写，无须发送到聊天。
4. 填写了配置时点击“保存设置”，重新打开检查第三方选项和模型。已保存的密钥应显示“已保存，留空继续使用”，不会回显明文。未填写时直接关闭设置即可。
5. 在工具条、回答卡、设置及历史面板的边缘或紧邻的透明空白处按住鼠标拖动，无须对准“拖动”按钮。检查按钮可点击、输入框能输入、回答文字可选中、历史和设置可滚动。面板周围的拖动区域会接收鼠标，远离面板的空白仍穿透。点击工具条的透明度按钮，检查滑块能否正常拖动。
6. 最后点击悬浮条最右边的 × 退出 Cue。告诉开发者“测完了”，若有问题说明发生在第几步。

本节界面回归不需要开始会话或授予采集权限。语音测试按上方“中文实时转写”步骤进行：对方暂定文字和最终文字持续更新输入框，按 Enter 才请求回答，不自动逐句发送。

## 日志

- macOS：`~/Library/Application Support/cue-go-remix/logs/cue.log`
- Windows：`%AppData%\cue-go-remix\logs\cue.log`

日志包含授权状态类别（如 `license-state`）和是否允许使用，以及时间、进程 ID、设置页打开、提供商选择、密钥框聚焦、保存结果、窗口尺寸、模型请求起止耗时、监听状态与退出事件，以及本地实时识别的首次出字、较慢解码耗时、排队时长、首次暂定与最终文字字数。仅记录固定类别和数值，不记录完整卡密、授权 Token、密钥、完整接口地址、模型名称、转录内容或问题/回答正文。文件达到 1 MiB 后，在下次启动时轮换为 `cue.previous.log`。

正常退出应有 `quit-request`、`shutdown-start`、`shutdown-done`。若窗口意外消失，开发者将结合最后一个操作事件、进程状态与系统崩溃记录判断，不能仅凭缺少退出日志就认定崩溃。
